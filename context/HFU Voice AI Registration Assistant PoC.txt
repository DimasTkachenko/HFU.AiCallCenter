Мы начинаем новый проект HFU Voice AI Registration Assistant PoC.
На этом шаге необходимо выполнить только Этап 1: создать каркас solution и базовых проектов. Не реализуй регистрационную бизнес-логику, OpenAI Realtime API, WebRTC, SignalR hub, AI tools или fake HFU registration.

# Контекст проекта

Это браузерный proof of concept голосового AI-ассистента для первичной регистрации пользователей HFU.
Будущая архитектура:
React + TypeScript frontend
        │
        ├── WebRTC → OpenAI Realtime API
        │
        ├── HTTP → ASP.NET Core Web API
        │
        └── SignalR → ASP.NET Core backend

ASP.NET Core backend
        ├── conversation session management
        ├── registration state
        ├── validation
        ├── AI tool handlers
        ├── reference data
        └── fake HFU registration
Главный архитектурный принцип:
Browser owns audio transport.
Backend owns conversation and registration state.
OpenAI owns speech-to-speech processing.
На текущем этапе создаётся только технический фундамент.

# Hfu.VoiceRegistration.Api

Тип:
ASP.NET Core Web API.
Project references:
Api → Application
Api → Infrastructure
Domain должен быть доступен API только транзитивно либо через Application contracts. Не добавляй прямую ссылку Api → Domain, если она не требуется для компиляции текущего минимального каркаса.
API должен содержать:
controllers или minimal API endpoints — выбери один последовательный подход;
endpoint GET /health;
Swagger/OpenAPI в development;
корректную dependency injection registration structure;
CORS configuration для локального frontend;
configuration placeholders для будущей OpenAI секции без реального ключа;
стандартный JSON setup;
HTTPS development support.
Предпочтительно использовать controllers, поскольку позднее появится несколько групп API и строгие DTO. Однако не создавай пустые контроллеры для будущих функций.
Ответ GET /health должен быть простым и пригодным для frontend, например:
{
  "status": "Healthy",
  "service": "Hfu.VoiceRegistration.Api"
}
Не добавляй authentication и authorization на этом этапе.

# Dependency injection structure

Создай extension methods для регистрации слоёв, чтобы Program.cs не стал местом накопления всех будущих зависимостей.
Например:
services.AddApplication();
services.AddInfrastructure(configuration);
На текущем этапе методы могут регистрировать только минимально необходимые зависимости или быть пустыми осмысленными точками расширения.
Избегай создания абстракций только ради абстракций.

# Конфигурация

Backend должен использовать стандартную configuration model.
Добавь секцию без секретов:
{
  "OpenAI": {
    "ApiKey": "",
    "RealtimeModel": ""
  }
}
В README явно укажи:
API key пока не нужен для Этапа 1;
позднее ключ должен передаваться через user secrets или environment variables;
ключ никогда не должен попадать во frontend.
Добавь development CORS origin через configuration, например:
{
  "Frontend": {
    "AllowedOrigins": [
      "http://localhost:5173"
    ]
  }
}
Не хардкодь CORS policy по всему приложению.
